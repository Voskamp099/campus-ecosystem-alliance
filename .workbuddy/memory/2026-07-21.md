## 追加修复：服务端模式 CSRF 403（影响所有鉴权后 POST）

现场跑 server 模式（localhost:3000）验证时发现：登录(GET/POST login)正常，但**退出、审核
(approve/reject)、删除、内容编辑等所有带 `Authorization: Bearer` 的 POST 都返回 403 CSRF**。
GET 类（4个 tab）因 CSRF 豁免不受影响，所以 file 模式下没暴露。

根因：`server/utils/csrf.js` 的 `getSessionIdentifier` 在请求带 `Authorization` 头时返回 JWT
作为标识，但 CSRF token 是在**未登录**的 `GET /api/csrf-token` 时签发的（标识=user-agent）。
标识不一致 → HMAC 校验永远失败。前端 admin.js 虽有 403 重试，但重试取的 token 仍是 user-agent
签发，依旧不匹配，故重试也失败。

修复：`getSessionIdentifier` 统一只用 `req.headers['user-agent']`（不再随 Authorization 切换）。
已重启服务验证：approve 由 403→200，退出改为纯客户端（清 token+跳转，404 无关）。

## 续做：my.html 登录后左侧菜单点不了 + 一直“加载中”

用户反馈：普通用户登录后进入“我的”页面（my.html），左侧几个菜单项点不了，所有列表一直显示“加载中”。

### 根因（关键）
- `my.html` 通过 `AllianceBootstrap.loadScripts([...])` **动态注入** `nav-auth.js` / `auth-guard.js`
  / `user-center.js`（`public/assets/bootstrap.js` 的 `loadScripts` 把 `<script>` 追加到 `body`）。
- 此时文档已解析完，`document.readyState === 'complete'`，**`DOMContentLoaded` 早已触发**。
- 这三个脚本的初始化都挂在 `document.addEventListener('DOMContentLoaded', ...)` 上——
  对动态注入的脚本该事件**不会再触发** → `user-center.js` 的 `init()` 永不执行：
  - `bindMenu()` 不跑 → 左侧菜单无点击事件 → 点不了；
  - `loadApplications/Registrations/Deliveries/MyPublish` 不跑 → 列表保持初始“加载中”占位。
- 注意：`nav-auth.js` 把 `window.AuthState` 在 IIFE 顶层**同步**定义，所以 `waitForAuthState()`
  能 resolve（不缺 AuthState），问题纯粹是 `init()` 没被调用。

### 修复（readyState 兜底，向后兼容静态引入）
- `public/assets/user-center.js` 启动段：`if (document.readyState==='loading') addEventListener('DOMContentLoaded',init) else init();`
- `public/assets/nav-auth.js` 同样改为 `bootNavAuth()` + readyState 兜底（保证动态注入时
  `verifyToken()`/`updateNav()` 也能跑，服务端模式 token 校验生效）。
- `public/assets/auth-guard.js` 同样改为 readyState 兜底（保证动态注入时未登录也能跳登录页）。
- `public/my.html`：三个脚本缓存戳 bump 到 `?v=202607211850`（nav-auth/auth-guard/user-center），
  loadScripts 数组 + fallback 数组两处同步改。

- server 启动后 `/assets/user-center.js?v=202607211850` 含 readyState 模式；my.html 引用新戳。
