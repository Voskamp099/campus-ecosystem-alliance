### 数据库（已完成，关键修复）
- **重要发现**：注册/登录的 MySQL 双写代码早已存在，但部署后实际是坏的——`docker-compose` 只加载 `database/schema.sql`，而该文件里的 `users` 表缺少 `verification_token/reset_token/login_count/email_verified_at` 等列；真正的带这些列的 `migrations/002_user_auth.sql` 从未被自动执行。所以 MySQL 在线时注册/登录会 SQL 报错，离线时静默降级到 JSON。这就是"感觉没接数据库"的根因。
- 重写 `database/schema.sql` 为单一规范 Schema（已合并 migrations 内容）：`users` 含全部鉴权列、`status ENUM('active','inactive','banned')`、`email_verified DEFAULT FALSE`；`activity_registrations`/`delivery_records` 列定义对齐代码实际用法。
- 新增 `server/scripts/init-db.js`：每次启动执行 `schema.sql`（CREATE TABLE IF NOT EXISTS 幂等）+ 对 `users` 做列存在性自检并补齐（兼容旧库）。已在 `server/index.js` 启动处调用（DB 不可用时仅告警不阻断，JSON 降级仍可用）。`package.json` 增加 `init-db` 脚本。
- 修复 `auth-service.createUser`：`email_verified` 由硬编码 `true` 改为 `false`（MySQL 与 JSON 两条路径），让邮箱验证流程真正生效（`verifyEmail` 仍在点链接后置 TRUE）。
- 同步修正 `migrate-to-mysql.js` 中 `activity_registrations`/`delivery_records` 的旧列名（event_id/recruit_id → activity_id/opportunity_id 等），避免新 schema 下迁移脚本报错。
